💻 Сервіс: Реєстр програмного забезпечення для лабораторій

Повнофункціональний веб-застосунок (Full-Stack) для автоматизації обліку програмних продуктів, контролю ліцензій та менеджменту запитів на встановлення софту в комп'ютерних лабораторіях університету.

* **Ключова сутність:** Програмний продукт (`Software Products`)
* **Варіант:** №12
* **Виконала:** Студентка групи КБ-12/1 Тураєва Єлизавета Дмитрівна

---

## 📂 Структура проєкту

* `/frontend` — Клієнтська частина застосунку (HTML, CSS, JavaScript).
* `/backend` — Серверна частина застосунку на Node.js / Express із тришаровою архітектурою та СУБД SQLite.

---

## 📌 Лабораторна робота №1. Фронтенд

### Опис проєкту
Веб-застосунок для створення та керування каталогом програмного забезпечення для лабораторій. Реалізовано CRUD-операції, валідацію та збереження даних у браузері.

### Функціонал
* Створення нових записів про програмні продукти.
* Відображення списку програм у вигляді інтерактивної таблиці.
* Редагування та видалення записів з таблиці.
* Вибір типу ліцензії за допомогою форми.
* Валідація обов’язкових полів форми перед додаванням.
* Захист від дублювання ідентичних програмних продуктів.
* Збереження стану та даних таблиці у `localStorage`.
* Автоматичне відновлення даних після перезавантаження сторінки.

### Запуск проєкту
1. Перейдіть у папку фронтенду та запустіть локальний сервер:
   ```bash
   cd frontend && python -m http.server 8000
(або використовуйте порт 8080)
2. Відкрийте у браузері: http://localhost:8000/

Як запустити бекенд

Відкрийте термінал і перейдіть у папку бекенду:
Bash

cd backend

Встановіть залежності:
Bash

Запустіть сервер у режимі розробки:
Bash

npm run dev

Сервер запуститься за адресою: http://localhost:3000

Реалізовані сутності
Users: (id, name, email)
Software: (id, name, version, developer)

Реалізовані можливості
REST API без бази даних (операції GET, POST, PATCH, DELETE).

Зберігання та обробка даних в оперативній пам’яті сервера (In-Memory storage).

Використання об'єктів DTO (Data Transfer Object) для безпечного обміну даними через мережу (CreateUserDto, UpdateUserDto).

Логування HTTP-запитів через впроваджений middleware logger.

Централізований обробник помилок (centralized error handler).

Серверна валідація вхідних запитів, пагінація, фільтрація та сортування потоку даних.

Підтримка методу PATCH для часткового оновлення полів сутностей.

Приклади запитів (cURL)
Створити нового користувача (Успіх - 201 Created):
Bash

curl -i -X POST http://localhost:3000/api/users -H "Content-Type: application/json" -d "{\"name\":\"Test\",\"email\":\"test@mail.com\"}"

Додати новий програмний продукт у реєстр (201 Created):
Bash

curl -i -X POST http://localhost:3000/api/software -H "Content-Type: application/json" -d "{\"name\":\"IntelliJ IDEA\",\"version\":\"2024.1\",\"developer\":\"JetBrains\"}"

Отримати список усіх користувачів (200 OK):
Bash

curl -i http://localhost:3000/api/users

Помилка валідації на сервері (400 Bad Request):
Bash

curl -i -X POST http://localhost:3000/api/users -H "Content-Type: application/json" -d "{\"name\":\"\"}"
📌 Лабораторна робота №3. SQLITE: Реляційна модель, схема даних, CRUD-запити, підключення SQLITE у бекенд
Як запустити бекенд

Відкрийте термінал і перейдіть у папку бекенду:
Bash

cd backend

Встановіть залежності:
Bash

npm install

Запустіть сервер у режимі розробки:
Bash

npm run dev

При першому запуску автоматично створиться файл data/app.db, застосуються міграції та база заповниться стартовими даними за допомогою механізму Seed.

Схема бази даних (взаємопов'язані таблиці з ON DELETE CASCADE)

Users: (id, email UNIQUE, name, createdAt)
Software: (id, name, version, developer)
Licenses: (id, softwareId FOREIGN KEY, licenseKey, status, validUntil)

Реалізовані можливості

Автоматична ініціалізація бази даних та генерація реляційних таблиць (db.js, dbClient.js, initDb.js).

Механізм Seed (seed.js) для автоматичного наповнення бази тестовими даними (користувачі, стартові програми типу IntelliJ IDEA, Docker Desktop та відповідні ліцензійні ключі).

Повний перехід на тришарову архітектуру (робота з БД повністю винесена в окремий ізольований шар репозиторіїв: Routes → Controllers → Repositories).

Складні SQL-запити: використання оператора JOIN для об'єднання реляційних таблиць (ендпойнт GET /api/software повертає список програм).

Обмеження на рівні бази даних: унікальність полів (UNIQUE), обов'язковість заповнення та системні індекси.

Примітки щодо безпеки (SQL Injection)
Згідно з навчальною метою лабораторної роботи, фільтрація та сортування в деяких запитах реалізовані через конкатенацію рядків. Це робить систему тимчасово вразливою до SQL Injection. Наприклад, передача ' OR 1=1; -- у параметри пошуку дозволяє обійти логіку вибірки. Ці вразливості будуть повністю усунені в наступних роботах за допомогою використання параметризованих запитів.

Приклади запитів (cURL)

Отримати весь список програмного забезпечення (Складний запит з JOIN - 200 OK):
Bash

curl -i http://localhost:3000/api/software

Створити та записати нову ліцензію для продукту в базу даних (201 Created):
Bash

curl -i -X POST http://localhost:3000/api/licenses -H "Content-Type: application/json" -d "{\"softwareId\":1,\"licenseKey\":\"AAAA-BBBB-CCCC-DDDD\",\"status\":\"active\",\"validUntil\":\"2027-12-31\"}"

Отримати користувачів із фільтрацією та сортуванням (200 OK):
Bash

curl -i "http://localhost:3000/api/users?sort=name&order=DESC"

Видалити програмний продукт та каскадно вичистити всі пов'язані ліцензії (200 OK):
Bash

curl -i -X DELETE http://localhost:3000/api/software/1
